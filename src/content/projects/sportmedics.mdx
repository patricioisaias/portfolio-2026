SportMedics es un sistema backend diseñado para la gestión integral de un gimnasio local ubicado en la comuna de La Cisterna. El sistema automatiza y controla los accesos, autenticación, facturación, empleados, inventario, miembros, notificaciones, horarios, suscripciones y entrenamientos.

Todo el proyecto fue construido aplicando patrones de **arquitectura de microservicios** utilizando el ecosistema de Spring Boot.

## Arquitectura del Sistema

El proyecto implementa patrones de arquitectura distribuida para asegurar el desacoplamiento, la escalabilidad y la mantenibilidad:

- **API Gateway:** Funciona como el único punto de entrada seguro para las peticiones de los clientes externos (navegadores o apps).
- **Eureka Server:** Encargado del registro y descubrimiento dinámico de todos los servicios desplegados.
- **Microservicios Independientes:** El sistema se divide en 10 módulos con responsabilidades únicas (Miembros, Suscripciones, Facturación, Inventario, Notificaciones, etc.).
- **Bases de Datos Aisladas:** Cada microservicio gestiona su propio esquema de base de datos MySQL, respetando estrictamente el patrón *Database-per-Service*.
- **Comunicación Interna:** Integración de *Feign Clients* para la comunicación eficiente entre los distintos microservicios.

## Roadmap y Próximos Pasos (Infraestructura Cloud)

> **Migración a AWS (En Planificación)**  
> Actualmente cursando el ramo de *Infraestructura Cloud*, el próximo gran hito de este proyecto es migrar su despliegue desde un entorno local hacia la nube pública de **Amazon Web Services (AWS)**.

Las siguientes mejoras arquitectónicas están planificadas para ser implementadas durante este semestre:

1. **Redes y Seguridad (VPC):** Diseño de una Nube Virtual Privada (VPC) estructurada con subredes públicas (para exponer únicamente el API Gateway) y subredes privadas (para proteger los microservicios y bases de datos), aislando el tráfico mediante Security Groups.
2. **Almacenamiento y Bases de Datos (Amazon RDS & EFS/EBS):** Migración de las bases de datos locales hacia **Amazon RDS** para garantizar alta disponibilidad. Integración de volúmenes de bloque y red (EBS y EFS) según los requerimientos de cada microservicio.
3. **Cómputo Escalable y Monitoreo (EC2, Auto Scaling, CloudWatch):** Despliegue de los contenedores en instancias **Amazon EC2** configuradas con **Auto Scaling Groups** para balancear la carga automáticamente, sumado a un monitoreo centralizado utilizando **CloudWatch**.
